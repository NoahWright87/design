# SceneFooter temporary effects

- Release: v1.6.0 is the first stable package version containing the fireworks API, automatic frequency, and configurable recycling pool. Keep package.json and both root package-lock.json version fields synchronized. The existing publish workflow publishes a stable release after merging to main only when the package version is ahead of npm; PRs receive a separate preview tag. Release preparation does not publish locally.
- Public exports: `createSceneEffects`, `useSceneEffects`, `SceneEffects`, `SceneEffect`, and `FireworkEffect` through the package entry point. Attach the stable handle to `SceneFooter effects={effects}` and share it through app props/context. `effects.trigger({ type: "firework", size?: "small" | "large", position?: { x, y }, color?: string })` returns whether any eligible attached scene accepted it.
- The hook creates a handle once per mount; the factory is SSR-safe. Subscription changes are separate from scene ownership. Per-event effects never enter JSON-serialized `sceneOptions` and do not recreate the scene. A handle intentionally shared by multiple footers broadcasts to all eligible instances.
- Controller owns readiness/visibility/quality: unavailable, loading, unsupported, offscreen (including the observer prewarm margin), hidden-tab, frozen, Still, static-fallback, reduced-motion, and destroyed triggers are dropped immediately, never queued. Active particles are cleared on offscreen/hidden/frozen transitions. Returning to view does not replay celebrations. Activity-specific decisions stay in consuming apps.
- `SceneInstance.trigger` and `clearEffects` are optional, preserving existing custom scenes. Horizon paints effects after clouds onto its existing sky canvas before `water.draw`, so both flat 2D and WebGL reflections include them without renderer changes. Normalized coordinates measure the sky band; colors accept CSS literals or one CSS variable (resolved at delivery; alpha discarded).
- `SceneFooter fireworksParticleLimit={8192}` configures a reusable particle pool, default 2,048, independently of quality. Every live visible Horizon trigger creates new fireworks; capacity recycles oldest submitted particles first (including pending launches), retaining newest shots. Expiry and pause return records to the spare pool; destroy releases active and spare records. Retained records stay at or below the limit and allocation is on demand. Live limit updates preserve scene identity; lowering a limit evicts oldest particles and releases excess spares. Finite limits round down to positive safe integers; nonfinite values restore 2,048. Tiny limits shorten incoming celebrations/detail instead of rejecting the event. Quality controls new-shell detail and existing frame/resolution limits. Groups finish within six seconds; no extra timers, assets, or animation loops.
- Updated defaults: each trigger chooses a fresh normalized sky position and a saturated three-color palette per shell. Explicit positions target the explosion center; explicit CSS colors/tokens override the random palette. Launch origins, angles, speeds, apex times, fuses, stagger intervals, and explosion scales/shapes vary. Analytic ballistic motion is frame-rate independent; some fuses last past the apex so shells start falling before exploding. Spark colors are precomputed when the shell is created to keep frames cheap.
- `SceneFooter fireworksFrequency={1.5}` requests an average 1.5 automatic shells/second. Default zero is off; negative/nonfinite values turn it off. The artificial eight-per-second cap was removed; high rates are paced by the scene's frame rate with no catch-up. This prop and fireworksParticleLimit are separate from serialized sceneOptions and live changes preserve the current instance. The controller remembers settings through loading; automatic frequency is zero while hidden/offscreen/frozen. Automatic/manual shells share the same recycling pool. Zero stops new launches while existing effects finish; visibility pauses clear particles and the next-launch clock.
- The demo's accepted/dropped badge was removed. Event handlers fire effects and let the decorative scene respond; the API's boolean remains an optional availability result for compatibility, not a capacity rejection or a required user-facing status. Demo controls include a frenzy button and particle limit.
